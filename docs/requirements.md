# MediON — 기능 명세 (requirements.md)

> 기획 배경과 범위는 [idea.md](./idea.md), 구현 방법은 [tech-spec.md](./tech-spec.md) 참고
> 우선순위: **Must**(해당 단계 필수) / **Should**(넣으면 좋음) / **Could**(여유 있을 때)
> 단계: **1차** 비대면진료 흐름 · **2차** 질문·답변 · **3차** 고도화 · **보류** 화상통화

## 1. 사용자 역할

| 역할 | 할 수 있는 일 | 가입 방식 |
|---|---|---|
| 게스트 (기본) | 로그인 없이 시작. 의사 찾기·의사 상세 열람 (2차: 공개 질문·답변 열람) | — |
| `patient` | 게스트 기능 + 예약, 결제, 처방전·약국 전송, 리뷰 (2차: 질문 작성) | 이메일 회원가입 |
| `doctor` | 진료 일정 확인, 진료 시작·완료, 처방전 작성 (2차: 답변 작성). 인증 승인 후에만 가능 | 의사 회원가입 → 면허 서류 제출 → 관리자 승인 |
| `admin` | 의사 인증 심사 | 시드 데이터로만 생성 |

> 앱 화면에는 "체험하기" 같은 데모 전용 진입점을 두지 않습니다. 포트폴리오 시연용 환자·의사 계정 정보는 README에 적어둡니다.

## 2. 핵심 흐름 (1차)

```
[환자] 의사 찾기 (증상 카테고리·진료과)
   ↓
[환자] 의사 상세 → 날짜·시간 선택 → 예약 (진료받을 사람, 증상 메모)
   ↓
[의사] 진료 일정에서 예약 확인 → 진료 시작 → 진료 완료 (+ 처방전 작성)
   ↓                                         ※ 화상통화는 보류. 진료는 상태 변경으로 진행
[환자] 진료비 결제 (토스페이먼츠 테스트 결제)
   ↓
[환자] 처방전 확인 → 근처 약국 선택 → 처방전 전송 (방문 수령 / 대상자만 배송)
   ↓
[환자] 조제·수령 상태 확인 → 진료 후기 작성
```

### 예약 상태

```
booked (예약됨) ──의사 진료 시작──▶ in_progress (진료 중) ──의사 진료 완료──▶ completed (진료 완료)
   │
   └──환자 취소(진료 시작 전) / 의사 취소──▶ cancelled (취소됨)
```

### 결제 · 처방전 · 약 수령 상태

```
결제:  ready (결제 대기) ──결제 승인──▶ paid (결제 완료)
                        └──실패──▶ failed (다시 결제 가능)

처방전: 진료 완료 시 발급 → 결제 완료 후 환자가 열람·약국 전송 가능

약 수령: sent (전송됨) → preparing (조제 중) → ready (수령 대기)  → received (수령 완료)
                                         └→ shipping (배송 중) ┘
```

## 3. 기능 목록

### A. 인증 · 공통 (1차)

| ID | 기능 | 우선순위 | 완료 기준 |
|---|---|---|---|
| A-0 | 시작 화면 | Must | 로고·서비스 소개, "로그인 없이 시작하기" 버튼, 로그인·의사 회원가입 링크. 진입하자마자 `/api/health`로 데모 서버를 깨우고 안내 문구 표시. 이미 로그인 상태면 역할별 첫 화면으로 이동 |
| A-1 | 로그인 없이 시작하기 | Must | 게스트로 홈에 들어가 의사 찾기·의사 상세 열람 가능 |
| A-2 | 역할별 화면 분기 | Must | 로그인한 역할에 따라 하단 탭과 첫 화면이 다르게 보임 |
| A-3 | 역할별 접근 제한 | Must | 환자는 의사 화면 URL에 직접 들어가도 접근 불가, API도 403 반환 |
| A-4 | 데모 안내 배너 | Must | 모든 화면에서 "포트폴리오용 데모" 표시 |
| A-5 | 데모 데이터 초기화 | Should | 시연용 계정이 만든 예약·결제 등이 하루 단위로 초기 상태로 복원 |
| A-6 | 로그인 필요 안내 | Must | 게스트가 예약하기·진료 내역·알림을 누르면 로그인 안내 바텀시트 표시, 로그인 후 하던 화면으로 복귀 |
| A-7 | 일반 회원가입 | Must | 이메일·비밀번호·닉네임 필수, 출생연도·성별 선택. 이용약관·개인정보(건강 정보 포함) 동의 필수 |
| A-8 | 이메일 로그인 | Must | 이메일·비밀번호 로그인, 실패 시 안내 문구 |
| A-9 | 의사 회원가입 신청 | Must | 이름·면허번호·전문과·소속 병원 입력, 의사 면허증 이미지 필수(전문의 자격증·재직 증명서 선택) |
| A-10 | 인증 심사 중 상태 | Must | 승인 전 의사는 심사 상태 화면만 보고, 진료·처방 API는 403 |
| A-11 | 관리자 인증 심사 | Should | 관리자가 제출 서류를 보고 승인/반려(사유 입력), 결과를 의사에게 알림. 1차에서는 시드 스크립트로 승인 처리해도 됨 |
| A-12 | 반려 후 재제출 | Could | 반려 사유를 확인하고 서류 다시 제출 |

### H. 의사 찾기 (1차)

| ID | 기능 | 우선순위 | 완료 기준 |
|---|---|---|---|
| H-1 | 증상 카테고리 홈 | Must | 홈에 증상 카테고리(감기·몸살, 위장장애, 피부질환 등) 그리드. 누르면 관련 진료과 의사 목록으로 이동 |
| H-2 | 의사 목록 | Must | 진료과·카테고리로 거른 인증 의사 목록. 카드에 소속 병원, 이름, 전문과, 재진 희망률(후기 수), **가장 빠른 예약 가능 시간** 표시 |
| H-3 | 목록 필터·정렬 | Should | "오늘 진료 가능", "진료받은 의사" 필터, 기본순 / 재진 희망률순 정렬 |
| H-4 | 의사 검색 | Could | 의사 이름·병원 이름·증상 키워드 검색 |
| H-5 | 의사 상세 | Must | 상단: 소속·이름·오늘 진료 시간. 탭: **의사 정보**(전문과, 약력, 진료 시간표) / **진료비**(나이대별 초진·재진 금액) / **후기** |
| H-6 | 예약 가능 시간 표시 | Must | 의사 상세에서 오늘부터 7일 날짜 선택 → 30분 단위 시간 칩. 지난 시간·이미 예약된 시간·점심시간은 선택 불가 |

### I. 예약 (1차)

| ID | 기능 | 우선순위 | 완료 기준 |
|---|---|---|---|
| I-1 | 의사 진료 시간표 | Must | 의사별 요일 진료 시간과 점심시간. 1차는 시드 데이터로 넣고 의사 화면에서 보기만 |
| I-2 | 예약하기 | Must | 시간 선택 → 진료받을 사람 선택 → 증상 메모(선택, 500자) → 예약 확정. 완료 화면에 예약 요약 표시 |
| I-3 | 중복 예약 방지 | Must | 같은 의사·같은 시간에 두 명이 동시에 예약해도 한 명만 성공, 나머지는 "이미 예약된 시간이에요" (409). DB 유니크 제약으로 보장 |
| I-4 | 내 예약 시간 겹침 방지 | Should | 같은 환자가 같은 시간에 다른 의사를 이중 예약하면 409 |
| I-5 | 진료받을 사람 | Should | 본인 또는 등록한 가족 중 선택. 진료비 계산에 쓰이도록 생년월일 필수 |
| I-6 | 가족 관리 | Should | 마이 → 가족 추가·삭제 (이름, 관계, 생년월일, 성별) |
| I-7 | 진료 내역 | Must | 예정 / 지난 진료 / 취소 탭. 카드에 의사·일시·상태·다음 할 일(결제하기, 처방전 보기 등) |
| I-8 | 예약 상세 | Must | 진행 단계(예약됨 → 진료 중 → 진료 완료 → 결제 → 처방전 → 약 수령)와 현재 단계 강조, 예약 정보, 증상 메모 |
| I-9 | 예약 취소 | Must | 환자는 진료 시작 전까지 취소 가능(사유 선택). 취소하면 그 시간이 다시 예약 가능해짐 |
| I-10 | 초진·재진 판정 | Must | 예약 시 같은 의사에게 완료된 진료가 있으면 재진, 없으면 초진. 진료비 계산에 사용 |

### J. 진료 진행 (1차, 화상통화 보류)

| ID | 기능 | 우선순위 | 완료 기준 |
|---|---|---|---|
| J-1 | 의사 진료 일정 | Must | 날짜별 예약 목록(시간순). 상태 뱃지, 환자 이름·나이대·성별, 증상 메모 미리보기 |
| J-2 | 예약 상세 (의사) | Must | 환자 정보, 진료받을 사람, 증상 메모, 초진·재진, 이 환자의 이전 진료 기록 |
| J-3 | 진료 시작 | Must | `booked` → `in_progress`. 환자 화면에 30초 안에 "진료 중" 표시 |
| J-4 | 진료 완료 | Must | 진료 요약(환자에게 보이는 안내) 입력, 처방 여부 선택 후 완료. **진료 완료 + 처방전 저장 + 결제 대기 생성 + 알림을 한 트랜잭션으로 처리** |
| J-5 | 의사 예약 취소 | Should | 진료 시작 전 의사가 취소(사유 필수), 환자에게 알림 |
| J-6 | 화상통화 자리 표시 | Must | 진료 중 화면에 "화상통화는 준비 중이에요" 안내 (보류 기능 표시) |

### K. 결제 (1차, 테스트 결제)

| ID | 기능 | 우선순위 | 완료 기준 |
|---|---|---|---|
| K-1 | 진료비 계산 | Must | 진료받을 사람의 나이대(만 1세 미만 / 1~64세 / 65세 이상)와 초진·재진으로 금액 결정. 금액은 목업 기준 데모 금액 |
| K-2 | 결제하기 | Must | 진료 완료 후 "결제하기" → 기본은 **데모 결제**(인증 없이 바로 완료). `VITE_PAYMENT_MODE=toss` 이면 토스페이먼츠 테스트 결제창. 어느 쪽이든 실제 돈은 나가지 않음 |
| K-3 | 결제 승인 | Must | 결제 성공 후 서버가 토스 승인 API 호출. **서버에 저장된 금액과 다르면 승인하지 않음**. 같은 요청이 두 번 와도 한 번만 처리 |
| K-4 | 결제 실패 처리 | Must | 실패·취소 시 사유 표시, 다시 결제 가능 |
| K-5 | 결제 내역 | Should | 마이 → 결제 내역(일시, 의사, 금액, 결제 수단) |
| K-6 | 영수증 | Could | 토스에서 받은 영수증 링크 열기 |

### L. 처방전 (1차)

| ID | 기능 | 우선순위 | 완료 기준 |
|---|---|---|---|
| L-1 | 처방전 작성 (의사) | Must | 진료 완료 화면에서 약 검색 → 약 추가(1회 투약량, 1일 횟수, 투약 일수, 복용 안내). 처방 없이 완료도 가능 |
| L-2 | 투약 일수 제한 | Should | 초진은 최대 7일까지만 입력 가능 (제도 세부 기준 확인 후 수정) |
| L-3 | 처방전 보기 (환자) | Must | **결제 완료 후** 열람. 처방전 번호, 발급일, 의사·병원, 약 목록, "데모 처방전" 워터마크 |
| L-4 | 약 정보 | Could | 약 이름을 누르면 효능·주의사항 (식약처 의약품 API) |

### M. 약국 · 약 수령 (1차)

| ID | 기능 | 우선순위 | 완료 기준 |
|---|---|---|---|
| M-1 | 근처 약국 찾기 | Must | 현재 위치(거부 시 기본 위치) 기준 약국을 카카오맵과 목록으로 표시. 이름·주소·거리·영업 여부 |
| M-2 | 수령 방법 선택 | Must | 기본은 **약국 방문 수령**. 배송은 대상자(섬·벽지 거주, 장기요양 수급, 장애, 희귀질환)라고 선택한 경우에만 가능, 배송지 입력 |
| M-3 | 처방전 전송 | Must | 약국 선택 → 전송 (데모: 실제 약국에 전송되지 않음). 한 처방전은 한 약국에만 전송 |
| M-4 | 조제·수령 상태 | Must | 전송됨 → 조제 중 → 수령 대기(방문) / 배송 중(배송) → 수령 완료. 예약 상세의 진행 단계에도 반영 |
| M-5 | 데모 상태 진행 | Must | 약국 쪽 화면이 없으므로 "데모: 다음 단계로" 버튼으로 상태를 넘김. 데모 기능임을 화면에 표시 |
| M-6 | 위치 권한 거부 처리 | Must | 거부 시 안내 문구와 기본 위치(광주광역시청)로 표시 |

### N. 진료 후기 (1차)

| N-1 | 후기 작성 | Should | 진료 완료(결제 완료) 건에 한 번만 작성. 재진 희망 여부, 태그(친절한 진료·자세한 설명·예약 시간 준수), 내용(선택) |

| N-3 | 재진 희망률 표시 | Should | 의사 목록·상세에 재진 희망률(%)과 후기 수 표시 |

### P. 오늘 약 복용 (1차 추가)

약국에서 약을 받은(수령 완료) 처방전으로 오늘 먹을 약을 시간대별로 보여주는 홈 카드. 데모 안내용이며 실제 복용은 처방전 안내·약사 설명을 따른다.

| ID | 기능 | 우선순위 | 완료 기준 |
|---|---|---|---|
| P-1 | 오늘 복용표 | Should | 수령 완료한 날을 1일째로, 약별 1일 횟수(1번 아침 / 2번 아침·저녁 / 3번 아침·점심·저녁 / 4번 이상 + 자기 전)와 투약 일수로 오늘 시간대·약 표시. 기간이 끝나면 사라짐 |
| P-2 | 복용 체크 | Should | 오늘 시간대를 눌러 먹었어요 체크/해제. 처방전·날짜·시간대마다 1번 (DB 유니크) |
| P-3 | 복용 알림 | Could | 복용 시간이 되면 알림 |

## 6. 개발 순서

1. ✅ **세팅**: 프론트·백엔드 기본 구조, DB 연결, 데모 배너, 휴대폰 크기 프레임
2. ✅ **인증과 역할**: 회원가입·로그인(JWT), 게스트 모드, 로그인 안내 바텀시트, 역할별 화면 분기, 마이·로그아웃 (A-0~A-3, A-6~A-8, G-1, G-2, G-5)
3. ✅ **의사 가입과 인증**: 의사 회원가입, 심사 중 화면, 관리자 승인/반려 + 알림 (A-9~A-11). 반려 후 재제출(A-12)은 이후
4. ✅ **의사 찾기**: 증상 카테고리 홈, 의사 목록·상세, 진료 시간표, 예약 가능 시간 (H-1, H-2, H-5, H-6, I-1)
5. ✅ **예약**: 예약하기·중복 예약 방지·진료 내역·예약 상세·취소 (I-2, I-3, I-7~I-10). 진료받는 사람은 본인만 (가족 I-5·I-6 은 이후)
6. ✅ **진료 진행과 처방전 작성**: 진료 일정, 진료 시작·완료, 처방전 작성 (J-1~J-4, J-6, L-1, L-2). 결제 요청 생성은 7단계, 알림은 9단계에서 같은 트랜잭션에 붙인다
7. ✅ **결제**: 진료비 계산, 토스 테스트 결제, 서버 승인 (K-1~K-5)
8. ✅ **처방전과 약국**: 처방전 보기, 약국 찾기, 전송, 수령 상태 (L-3, M-1~M-6)
9. ✅ **알림과 후기**: 진료 알림, 후기 (F-1, F-2, N-1~N-3)
10. **배포**: Vercel, Render, Aiven MySQL, README 시연 계정 작성
11. **2차**: ✅ 질문·답변, 질문 → 예약 연결 (B-1, B-2, B-5, B-6 삭제, C-1~C-7, D-1~D-4, D-6, F-3), ✅ 홈 오늘 약 복용 (P-1, P-2) / 남은 것: 근처 병원 찾기(E), 질문 수정·사진·임시저장(B-6 수정, B-3, B-4), 자주 쓰는 문구(D-5)
12. **이후**: Should → Could 순서, 화상통화 보류 해제 여부 결정

> 각 단계가 끝날 때마다 동작하는 상태를 유지해서, 중간에 멈춰도 완성된 결과물이 남도록 진행합니다.
